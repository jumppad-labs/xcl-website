<Prose>

Passwords, tokens and other secrets travel through a configuration like any
other value: they are set in a block, referenced from other blocks, passed into
modules and published by outputs. Declaring them sensitive keeps them out of
everything xcl and your application print, log or report, without changing how
the configuration is written.

## Declaring a sensitive field

Give the field the type `types.Sensitive[T]`. That is the only change; the
configuration sets it exactly as it would set a plain field:

```go title="example/appconfig/resources/resources.go"
type Database struct {
	Driver   string `xcl:"driver" json:"driver"`
	Host     string `xcl:"host" json:"host"`
	Port     int    `xcl:"port" json:"port"`
	Name     string `xcl:"name" json:"name"`
	Username string `xcl:"username" json:"username"`

	// Password is sensitive: printing, logging or marshalling it shows
	// "(sensitive)", and the program reads the real value with Reveal only
	// where it is used
	Password types.Sensitive[string] `xcl:"password" json:"password"`
}
```

```hcl title="example/appconfig/config/app.xcl"
password = env("DB_PASSWORD")
```

The same declaration works on the types a plugin provides. Plugin types may use
`types.Sensitive[string]`, `[int]`, `[int64]`, `[float64]`, `[bool]`,
`[[]string]` and `[map[string]string]`; a plugin type using another fails to
load, naming the type and the field. In tests, build one with
`types.NewSensitive("hunter2")`.

## Unwrapping in application code

`.Reveal()` is the only way to the real value. Call it where the value is
used, such as when building a connection string, and never print or log what
it returns: once revealed, a value is an ordinary value and is no longer
protected.

```go title="example/appconfig/main.go"
// databaseURL builds the connection string for the database. It holds the real
// password, read with Reveal, so it must not be printed or logged.
func databaseURL(db *resources.Database) string {
	connection := url.URL{
		Scheme: db.Driver,
		User:   url.UserPassword(db.Username, db.Password.Reveal()),
		Host:   net.JoinHostPort(db.Host, strconv.Itoa(db.Port)),
		Path:   "/" + db.Name,
	}

	return connection.String()
}
```

A plugin's provider does the same, calling `Reveal()` only where it connects.
It must not log the revealed value, put it in an error, or copy it into a field
that is not sensitive. Logging the sensitive field itself is safe, since it
writes `(sensitive)`.

## Sensitivity follows the value

A value derived from a sensitive value is sensitive too: one referenced from a
sensitive field, interpolated into a string, passed through a function, passed
into a module input, or published by an output. An output holds its sensitive
parts as `types.Sensitive` values, so an output whose value is a whole database
block reads back as a map whose `password` entry is a
`types.Sensitive[string]`, before and after a reload.

## When a sensitive value meets a plain field

A sensitive value can only be assigned to a field declared sensitive. In
configuration, assigning one to a plain field fails validation, so `Validate`
and `Apply` refuse the configuration before anything is created:

```text
field "note" of resource.audit.main is not declared sensitive and cannot be
assigned a sensitive value
```

In Go, converting or looking up an entity into a type whose matching field is
plain fails with `xcl.ErrTypeMismatch`. The `*xcl.TypeMismatchError` detail
names the field. There is no automatic unwrap: declare the field
`types.Sensitive[T]` in your own type too.

```go
_, err := xcl.Find[PlainDatabase](c, "resource.database.main")
// entity "resource.database.main" field "password" is sensitive,
// main.PlainDatabase declares it as a plain value
```

## Your own JSON and templates show the marker

A sensitive value formats as `(sensitive)` everywhere Go formats it: every
`fmt` verb, `log/slog`, `encoding/json` and `text/template`. The application
config example prints its configuration as JSON with `json.MarshalIndent`, and
the password comes out as the marker:

```json
"username": "app",
"password": "(sensitive)",
```

To put the real value in your own output, unwrap it with `.Reveal()` first,
knowing that it is then unprotected.

## What xcl shows, and what it keeps

- **Logs, events and errors** show only `(sensitive)`. Event data carries the
  marker at both data levels, and a function that fails on a sensitive argument
  shows the marker in place of the value in its error.
- **State** keeps the real value, so a configuration that loads it reads the
  value back unchanged. The state file therefore holds the secret in plain
  text.
- **Configuration text** from `EncodeEntity` and `EncodeSavedEntity` writes
  `password = "(sensitive)"`. Pass `xcl.RevealSensitive()` to write the real
  value.
- **The resource printer** shows the marker in every format.
  `logger.WithRevealSensitive(true)` shows real values.

A value read back from event data has no real value to show, so it is written
as the marker even when revealing is asked for.

State keeps the real value, in plain text unless you give xcl a key: see
[State masking](/state-masking/) to encrypt it.
