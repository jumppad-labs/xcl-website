<Prose>

Without it, an application that uses an external plugin builds or ships the
plugin binary itself. The GitHub registry removes that step: name the
repository and the release, and xcl does the rest when plugins load.

## Declaring a plugin

Create a GitHub registry with `registry.NewGitHub`, or `xcl.GitHubRegistry` in
Python, register each plugin by repository and release tag, and give the
registry to the `Config` like any other:

<CodeTabs>
  <div slot="go">

```go title="main.go"
gh := registry.NewGitHub()
gh.RegisterPlugin("jumppad-labs/xcl-plugin-docker", "v0.4.1")

c, err := xcl.NewConfig(
	xcl.WithRegistry(local), // your own types and plugins
	xcl.WithRegistry(gh),    // plugins from GitHub releases
)
if err != nil {
	return err
}
```

  </div>
  <div slot="python">

```python title="main.py"
github = xcl.GitHubRegistry()
github.register_plugin("jumppad-labs/xcl-plugin-docker", "v0.4.1")

with xcl.Config(
    registries=[
        local,   # your own types and plugins
        github,  # plugins from GitHub releases
    ],
) as cfg:
    ...
```

  </div>
</CodeTabs>

Registering only records, as on the local registry. The plugin is named after
the repository, here `xcl-plugin-docker`, and is installed, or found in the
cache, at the start of the first `Validate`, `Apply`, `Destroy`, `Diff` or
`Load`. A GitHub registry wraps a local registry, so `registry.Register` and
`RegisterType` work on it too, and it loads in the order it was given beside any other registry.

## Pinning a version

A plugin is pinned to one exact release tag: `v<major>.<minor>.<patch>`, with
an optional pre-release suffix such as `v0.5.0-rc.1`. There is no `latest` and
no range, so the same configuration always runs the same plugin, and nothing
checks for newer releases. A wrong declaration is a programmer error and
panics at the `RegisterPlugin` line, naming the plugin, before anything is
downloaded:

<CodeTabs>
  <div slot="go">

```go title="main.go"
gh.RegisterPlugin("jumppad-labs/xcl-plugin-docker", "latest") // panics
gh.RegisterPlugin("jumppad-labs/xcl-plugin-docker", "~0.4")   // panics
gh.RegisterPlugin("jumppad-labs/xcl-plugin-docker", "0.4.1")  // panics, the tag has a v
gh.RegisterPlugin("xcl-plugin-docker", "v0.4.1")              // panics, not owner/repo
```

  </div>
  <div slot="python">

```python title="main.py"
github.register_plugin("jumppad-labs/xcl-plugin-docker", "latest")  # fatal when the Config is created
github.register_plugin("jumppad-labs/xcl-plugin-docker", "~0.4")    # fatal
github.register_plugin("jumppad-labs/xcl-plugin-docker", "0.4.1")   # fatal, the tag has a v
github.register_plugin("xcl-plugin-docker", "v0.4.1")               # fatal, not owner/repo
```

In Python, `register_plugin` only records the declaration. The same rule is
applied when `xcl.Config` is created, before anything is downloaded, but not
as a Python exception: the engine panics, the panic is not recovered, and the
process exits with the message naming the plugin on standard error. Check a
repository and version before declaring them when they come from input.

  </div>
</CodeTabs>

Draft releases are never installed.

## What a release must contain

The registry installs exactly the layout the plugin template publishes, and
nothing else. For a repository called `xcl-plugin-docker` at `v0.4.1`:

- `xcl-plugin-docker-0.4.1-index.xcl`, the release's index. It is required:
  a release without one isn't a plugin release, and is refused. It names the
  plugin and its version, and lists each platform the plugin is built for,
  among linux, darwin and windows on amd64 and arm64, with the name of that
  platform's zip and the zip's SHA-256:

  ```hcl
  plugin {
    name    = "xcl-plugin-docker"
    version = "0.4.1"
  }

  executable {
    protocol = [1]

    platform "linux" "arm64" {
      asset    = "xcl-plugin-docker-0.4.1-linux-arm64.zip"
      checksum = "sha256:75e9015748ebadd95ce2936b60276d77c89c5b131c7dbcce67d3ceef66920ce9"
    }
  }
  ```

  A release may leave a platform out; installing on that platform then fails,
  naming the platforms the release offers. The index holds literal values
  only, and every platform must have a checksum.
- one zip per platform, `xcl-plugin-docker-0.4.1-<os>-<arch>.zip`, holding
  the plugin binary and, at its root, an `xcl-plugin.xcl` manifest naming the
  plugin, its version, the command that starts it and the one platform it was
  built for. The manifest must agree with the index.
- optionally `xcl-plugin-docker-0.4.1-index.xcl.sig`, an ASCII-armoured
  detached OpenPGP signature over the index.

`0.4.1` is the tag without its `v`. The parts of each name may be separated
by `-`, as here and in the plugin template, or by `_` throughout
(`xcl-plugin-docker_0.4.1_index.xcl`); the registry finds the index under
either name, and takes every zip's name from the index.

The plugin template's `make dist` and release workflow produce all of this
from a pushed version tag. Any other tool producing the same names and
formats works too.

## Trusting signing keys

Give the registry the public keys you trust, and a plugin is used only when
its release's index is signed by one of them:

<CodeTabs>
  <div slot="go">

```go title="main.go"
key, err := os.ReadFile("./keys/acme-plugins.asc")
if err != nil {
	return err
}

gh := registry.NewGitHub(registry.GitHubTrustedKeys(string(key)))
gh.RegisterPlugin("acme/xcl-plugin-billing", "v2.0.1")
```

  </div>
  <div slot="python">

```python title="main.py"
from pathlib import Path

key = Path("./keys/acme-plugins.asc").read_text()

github = xcl.GitHubRegistry(trusted_keys=[key])
github.register_plugin("acme/xcl-plugin-billing", "v2.0.1")
```

  </div>
</CodeTabs>

A release signed by another key, or not signed at all, is refused and nothing
is kept. The index holds every zip's checksum, so signing it signs every zip.
Without trusted keys signatures are not checked, and unsigned releases
install. A key that cannot be read fails the load, naming the `github.com`
registry.

## Private repositories

Releases of a private repository install when a GitHub token is available.
The registry uses the token given with `registry.GitHubToken`, otherwise the
`GITHUB_TOKEN` environment variable, then `GH_TOKEN`, and sends it with every
request:

<CodeTabs>
  <div slot="go">

```go title="main.go"
gh := registry.NewGitHub(registry.GitHubToken(os.Getenv("ACME_PLUGINS_TOKEN")))
gh.RegisterPlugin("acme/xcl-plugin-billing", "v2.0.1")
```

  </div>
  <div slot="python">

```python title="main.py"
import os

github = xcl.GitHubRegistry(token=os.environ["ACME_PLUGINS_TOKEN"])
github.register_plugin("acme/xcl-plugin-billing", "v2.0.1")
```

  </div>
</CodeTabs>

Public repositories need no token. GitHub answers a request for a private
repository without a token as if it did not exist, so without one the error
names the repository and says it was not found or needs a token.

## The cache

Installed plugins are kept under the xcl home directory, in
`~/.xcl/cache/plugins`, one entry per repository, version and platform:

```text
~/.xcl/cache/plugins/github.com/jumppad-labs/xcl-plugin-docker/v0.4.1/linux_arm64/
  xcl-plugin-docker-0.4.1-index.xcl
  xcl-plugin-docker-0.4.1-index.xcl.sig
  xcl-plugin-docker-0.4.1-linux-arm64.zip
  xcl-plugin-docker
  xcl-plugin.xcl
  README.md
  LICENSE
```

The entry holds the index, its signature when the release has one, this
platform's zip and the files extracted from it. Only this platform's zip is
downloaded.

Choose another location with `registry.GitHubCacheDir`, for example a
directory inside your project or a CI cache:

<CodeTabs>
  <div slot="go">

```go title="main.go"
gh := registry.NewGitHub(registry.GitHubCacheDir("./.xcl/plugins"))
```

  </div>
  <div slot="python">

```python title="main.py"
github = xcl.GitHubRegistry(cache_dir="./.xcl/plugins")
```

  </div>
</CodeTabs>

- **Offline.** A version already in the cache is used without contacting
  GitHub, so applies work with no network access.
- **Checked on every start.** Every time a cached plugin is started it is
  verified again: the signature over the index against the application's
  current trusted keys when it gives any, the zip against its checksum in the
  index, the zip's manifest against the index, and the binary against its
  copy in the zip. A changed file is refused before the
  plugin runs.
- **Written in one step.** A plugin is downloaded and verified in a temporary
  directory and moved into place only once it passes, so a failed or
  interrupted download leaves nothing usable behind.
- **Never pruned.** Old versions stay until you delete them by hand.

## Errors

A plugin that cannot be installed fails the first operation with a
`*xcl.PluginLoadError` naming the plugin and the `github.com` registry. It
wraps a `*xcl.PluginInstallError`, which names the `Repository`, `Version` and
`Platform`, and matches one of two errors:

- `xcl.ErrPluginNotFound`: the release does not exist, has no index, or
  offers no build for this platform, or the repository is private and no
  token was given. A missing build names the platforms the release offers.
- `xcl.ErrPluginVerification`: the index is incomplete or names another
  plugin or version, the zip does not match its checksum in the index, the
  zip's manifest disagrees with the index, a cached file was changed, or,
  with trusted keys, the index is unsigned or its signature is not from a
  trusted key.

<CodeTabs>
  <div slot="go">

```go title="main.go"
err := c.Apply("./config")

var install *xcl.PluginInstallError
if errors.As(err, &install) {
	log.Printf("cannot install %s %s for %s", install.Repository, install.Version, install.Platform)
}

if errors.Is(err, xcl.ErrPluginVerification) {
	log.Print("refusing a plugin that did not verify")
}
```

  </div>
  <div slot="python">

```python title="main.py"
try:
    cfg.apply("./config")
except xcl.PluginVerificationError:
    print("refusing a plugin that did not verify")
except xcl.PluginNotFoundError as err:
    details = err.details
    print(f"cannot install {details['repository']} {details['version']} for {details['platform']}")
```

In Python, the failed operation raises `xcl.PluginNotFoundError` or
`xcl.PluginVerificationError`, and `err.details` carries the `repository`,
`version` and `platform`.

  </div>
</CodeTabs>
