# The configuration text guide shows encoding from Python

The configuration-text guide on xcl.dev now shows Python's `cfg.encode_entity` beside Go's `xcl.EncodeEntity` wherever it said converting a live entity, provider-filled values or references was not yet available from Python. It names the four choices and highlighting for Python, shows the saved-record call taking the same choices, and gains a section on including empty attributes. The events page explains how to encode the entity an event carries.

> Derived from project xcl (jumppad-labs), spec/plan 20261016064106-8931613a-python-encode-entity. See the project-level record for the full feature.

## What changed in this repo

- `src/pages/configuration-text.mdx`:
  - the intro names `cfg.encode_entity` and `cfg.encode_saved_entity`;
  - every Python tab shows the working call: converting an entity (with its asyncio form), saved data with choices, an event's entity, `include_computed=True`, `reveal_sensitive=True`, `show_references=True`, and `highlight=True` on both terminal highlighting tabs;
  - a new "Empty attributes" section covers `xcl.IncludeEmpty()` and `include_empty=True`;
  - the Sensitive values section gains a Go and Python tab, and says that a kept event entity shows the engine's current value with reveal, unlike Go;
  - the editor-theme and renderer notes still say Python offers `highlight=True` only.
- `src/pages/events.mdx` mentions `cfg.encode_entity(event.entity())` and its reveal behaviour.

## Why

The configuration-text guide is xcl.dev's Python documentation for encoding, and it described a gap that xcl-lang's `encode_entity` now closes. These pages should go live with the xcl-lang release that ships `encode_entity`.
