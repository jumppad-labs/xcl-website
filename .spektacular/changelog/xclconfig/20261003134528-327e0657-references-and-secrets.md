# Sensitive values documentation

The documentation site has a new Sensitive values guide explaining how to declare a field sensitive, unwrap it with `Reveal()`, the errors raised when a sensitive value meets a plain field, and that the application's own JSON and templates show `(sensitive)`. The example pages now match what the examples print, with passwords shown only as the marker.

> Derived from project xcl, spec/plan 20261003134528-327e0657-references-and-secrets. See the project-level record for the full feature.

## What changed in this repo

- New page `/sensitive-values/`, linked from the Guides navigation, a home page feature card and the site README.
- Home page struct, application-config example (JSON output and "what to notice"), plugins example (sensitive password field, `connect` with `Reveal()`, new `db_password` default) and plugin-logging page refreshed to match the xcl examples.

## Why

The spec requires the documentation site to describe sensitive values and the example pages to quote what the examples now produce.
