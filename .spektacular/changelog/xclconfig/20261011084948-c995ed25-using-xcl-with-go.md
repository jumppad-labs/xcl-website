# Go and Python guides and API references on xcl.dev

xcl.dev now has a step-by-step guide for Go and one for Python, each building a working program from an empty directory, and generated API references for both languages at `/api/go/` and `/api/python/`, shown in the site's own layout. The references are built from the release the site advertises, the same release the hero badge shows. The guides and references are reachable from the navigation, the footer and the home page.

> Derived from project xcl (xcl), spec/plan 20261011084948-c995ed25-using-xcl-with-go. See the project-level record for the full feature.

## What changed in this repo

- New pages `src/pages/using-xcl-with-go.mdx` and `src/pages/using-xcl-with-python.mdx`, verified by running their snippets against xcl v0.5.3 and `xcl-lang` 0.5.3.
- Release pin `src/config/release.json` (`v0.5.3`), re-exported by `src/config/site.ts` as `xclRelease` and `xclLangVersion`, with `goReferenceURL` now `/api/go/`, a new `pythonReferenceURL` and `goPkgDevURL`. The hero badge and both guides' install lines read the pin.
- `scripts/api-docs/` (`generate.sh`, `python.py`, `go-frontmatter.tmpl`, `requirements.txt`, `pdoc-templates/frame.html.jinja2`) behind `npm run api-docs` and `make api-docs`, writing fragments to the git-ignored `generated/api/`. doc2go v0.12.2 and pdoc 16.0.0 are pinned with their reasons.
- Routes `src/pages/api/go/[...path].astro` and `src/pages/api/python/[...path].astro`, the shared `src/lib/api-fragments.ts`, `src/components/ApiReference.astro` and `src/styles/api-reference.css`. Without fragments the build warns locally and fails when `CI` is set.
- `.github/workflows/deploy.yml`: `workflow_dispatch`, Go 1.27.x, Python 3.12 and a "Generate API references" step before the build.
- Navigation: both guides first in Guides; a new "API" dropdown after "Language"; items carry `hideOnSmall` (Features and API). Footer: "Go API" and "Python API". Home page: closing banner offers both guides; the Documentation section lists both guides and both references.
- README: page table rows for the guides and references, and an "API references" section.

## Why

The site is the home of xcl's documentation. Developers needed one walkthrough in their own language and an API reference for each, matching the release they install.
