# Plugin template guide and release signing key

The documentation site has a new guide, "Plugin template", that explains the standard plugin layout and how to start, build, run, release and install a plugin from the template repository. The site also now publishes the jumppad-labs release signing public key, so applications can fetch it and trust the template's signed releases.

> Derived from project xcl (github.com/jumppad-labs/xcl), spec/plan 20261009092551-82db0140-plugin-template. See the project-level record for the full feature.

## What changed in this repo

- **`public/keys/jumppad-labs-releases.asc` (new):** the armoured public key, served at `/keys/jumppad-labs-releases.asc`, fingerprint `15BD A684 3A1F A0EA D1AA  5190 F775 DA00 AFD4 B502`.
- **`src/pages/plugin-template.mdx` (new):** the guide page. It covers:
  - the layout and the change decision
  - starting from the template
  - building and testing
  - in-process and separate-program runs
  - releasing
  - installing with the GitHub registry
  - verifying releases against the published key
- **`src/config/site.ts`:** gains `templateURL`.
- **Navigation and links:**
  - `src/components/Nav.astro` lists "Plugin template" under Guides.
  - `src/pages/registries.mdx` and `src/pages/examples/plugins.mdx` link to the new page.

## Why

Plugin authors need one place on the site that shows the standard layout and the path from "Use this template" to an installed, signed plugin. Applications need a stable URL for the key that signs the template's releases.
