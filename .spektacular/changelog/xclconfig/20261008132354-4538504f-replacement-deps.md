# Replacement and dependency changes

The documentation site now explains how xcl plugins decide whether a resource is unchanged, updated in place or replaced, and how plans show replacements and the reasons for them. A new guide for plugin authors covers the answer a plugin gives, what it is told about its dependencies, and the order an apply works in. The diff and plugin example pages show real plans with replacements.

> Derived from project xcl (jumppad-labs/xcl), spec/plan 20261008132354-4538504f-replacement-deps. See the project-level record for the full feature.

## What changed in this repo

- **New guide page "Unchanged, update or replace"** (`/replacement/`), linked from the Guides menu. It covers:
  - what `Changed` answers, and `DefaultChanged`;
  - the dependency rules;
  - decide-then-act and the destroy-first order;
  - the real Docker network and container overrides, with the container's reading its dependency list;
  - the real plan output;
  - the external plugin protocol.
- **Home page:** the plugins feature card now describes the three answers and links to the guide.
- **Diff page:**
  - The replace action has three reasons: last apply failed, cannot be updated in place, or a dependency is replaced.
  - The rendered sample shows one replacement per reason.
  - The JSON sample shows `reason` and `replaced_dependencies`.
- **Plugin example page:**
  - It quotes the network, container and template replace rules and describes the subnet tests.
  - It replaces the old walkthrough, which showed a container image change as an in-place update, with the `config-subnet` plan and apply. The output was captured from a real run.

## Why

xcl's plugins can now express changes they can't make in place, and plans explain the replacements that follow. The site is where plugin authors and users learn that behaviour, so it needed a guide reachable from the Guides menu, and its diff and example pages had to match what the program now prints.
