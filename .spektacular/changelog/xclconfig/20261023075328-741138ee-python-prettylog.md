# Events page shows Python's built-in pretty logger

The events page's "A pretty receiver" section now shows Python's built-in pretty logger, `xcl.prettylog`, with its one-line setup and a sample of its output, in place of a hand-written Python receiver. The delivery guarantees also say that both Python clients deliver events one at a time, in order.

> Derived from project xcl (spektacular), spec/plan 20261023075328-741138ee-python-prettylog. See the project-level record for the full feature.

## What changed in this repo

- `src/pages/events.mdx`: the pretty-receiver Python tabs show `xcl.prettylog.handler(sys.stderr, xcl.prettylog.level_from_env())` with processed event data and sample output; the hand-written receiver and its ANSI escape table are gone; new sentences cover the asyncio client, the `logger=` route, rendering from the saved record, reports beneath configuration mistakes and the guidance line; the "Ordered, one at a time" guarantee covers both Python clients. No page was added, renamed or removed.

## Why

The xcl Python package now ships the receiver itself, so the site points readers at it rather than at code they would have to copy. Publish after the xcl-python release that includes `xcl.prettylog`.
